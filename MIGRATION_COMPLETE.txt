  □ Note connection string

STEP 2: Environment Configuration (2-3 min)
  □ Set DATABASE_URL in .env.local:
    DATABASE_URL=postgresql://user:password@localhost:5432/database_name
  □ Test connection: psql $DATABASE_URL -c "SELECT 1"

STEP 3: Code Testing (1-2 hours)
  □ Run your existing test suite
  □ Prioritize design request routes (they were hand-tested)
  □ Test order/payment routes
  □ Test admin routes

STEP 4: Staging Deployment (1-2 hours)
  □ Deploy code to staging environment
  □ Run smoke tests on key endpoints
  □ Monitor database logs for 30 minutes
  □ Verify no connection errors

STEP 5: Production Deployment (1 hour)
  □ Set DATABASE_URL in production environment
  □ Deploy code to production
  □ Monitor closely for 2-4 hours
  □ Watch for database connectivity issues
  □ Have rollback plan ready (just change DATABASE_URL)

SUPPORT & TROUBLESHOOTING
═════════════════════════════════════════════════════════════════════════════

Common Issues:

1. "DATABASE_URL not set"
   → Add to .env.local: DATABASE_URL=postgresql://...

2. "Failed to connect to PostgreSQL"
   → Verify PostgreSQL is running
   → Check connection string format
   → Test with: psql $DATABASE_URL -c "SELECT 1"

3. "Column not found" error
   → Database schema migrations auto-run on startup
   → Check database logs for migration errors
   → Verify database user has CREATE TABLE permissions

4. "TypeError: NextResponse is not defined"
   → Verify NextResponse import is present at top of file
   → Check: import { NextResponse } from "next/server"

For more help, see MIGRATION_QUICK_REFERENCE.md troubleshooting section.
